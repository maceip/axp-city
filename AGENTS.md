# AXP City working contract

- This repository is `maceip/axp-city`. Verify directory, remotes, status and branch before edits; fetch before choosing a base. Preserve user artwork, persisted integration data and the separate `ai-game-studio` symlink.
- The accepted scope is the core **Town workshop** and its repository atlas: a rotating Globe.gl world of language continents, topic regions, and read-only repository districts. Keep Phaser 4 as the city renderer, one integer-grid world model in `src/core`, and one default core server. Only the visible view owns input; pause the hidden globe. Do not restore the retired GitHub/Trending workers or civic/HUD collage without an explicit request.
- Terrain, placement, road connectivity and vehicle movement must read the same world state. Simulation runs independently of frame rate, camera visibility and sprites. Asset footprints and ground anchors are explicit; do not repair geometry with zoom-dependent scale changes.
- Browser saves are versioned and validated. Do not silently import or transform old SQLite addresses or fractional lot geometry. Core startup must not open those stores, load credentials or start integration workers. Preserve the integration modules for deliberate future migration.
- Automatic CI runs `npm test`, `npm run typecheck`, `npm run build`, and `npm run test:operations`. Green automatic CI does not prove browser rendering or interactions. Keep `npm run test:e2e` available as a manual Chromium, Firefox and WebKit check before milestones or relevant renderer, input or save changes; it is not required after every edit. Use the standard pytest-playwright setup in `e2e/README.md`; do not rebuild browser lifecycle or hosted-provider selection. Frame-time benchmarks remain explicit `npm run test:performance` measurements. Historical `legacy_ui` checks are superseded, not passing coverage.
- During manual browser acceptance, inspect actual near/mid/far screenshots and exercise mouse/touch placement, rejection, save/load, camera and recovery. A compile, screenshot file or unit count alone does not prove those outcomes. Hardware performance claims require the actual driver and named device. Do not call SwiftShader a hardware measurement.
- Production deployment is separate from local implementation. Read `docs/DEPLOY.md` before deployment; preserve server data and unrelated services. Report actual tested revision and remaining limitations honestly.
